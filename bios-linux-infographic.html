The Linux BIOS River Flow

Watch how the legacy BIOS passes control to GRUB, which navigates the disk, loads the kernel, and transitions to Protected Mode.

BIOS & POST
CPU starts at 0xFFFF0 · Hardware tested
Boot Order: HDD, CD-ROM, USB
MBR Loading
Reads first 512 bytes from disk
Loaded at 0x7C00 · Signature 0x55AA
GRUB2 Bootloader
Scans partition table & filesystem
boot.img (Stage 1): 512 bytes in MBR
core.img (Stage 1.5): Post-MBR gap, contains ext4 driver
grub.cfg (Stage 2): Menu configuration
Kernel & Initrd
GRUB loads OS files into memory
vmlinuz (Kernel) + initrd.img (RAM Disk)
Protected Mode Transition
BIOS interrupts disabled forever
Jumps to startup_32() · 32/64-bit mode
Linux Kernel & systemd
Mounts root FS and starts PID 1
systemd starts services and login prompt

🐧 The Linux Boot Philosophy

Unlike Windows, which uses a highly specific chain (BOOTMGR -> BCD -> winload), Linux uses a flexible, multi-stage bootloader (GRUB2) that can read almost any filesystem, allowing the user to choose between multiple kernels or even different operating systems at boot time.
