Linux UEFI Boot

The modern Linux boot process using GPT, ESP, and Secure Boot. From SEC phase to systemd.

The Definition

The Linux UEFI boot process leverages 64-bit firmware to load `.efi` executables from the EFI System Partition (ESP). It uses a Secure Boot chain (often starting with `shim.efi`) to verify the `grubx64.efi` bootloader. GRUB then loads the Linux kernel (`vmlinuz`) and initial RAM disk (`initrd`), calls `ExitBootServices()`, and hands control to the Linux kernel to start `systemd`.

⚙️ The Technical Analogy
Secure Boot requires a cryptographic chain of trust. UEFI verifies shim.efi (signed by Microsoft). shim.efi verifies grubx64.efi (signed by Canonical).

GRUB uses UEFI Boot Services to read /boot/grub/grub.cfg and load vmlinuz + initrd. Finally, GRUB calls ExitBootServices() before jumping to the kernel, leaving only Runtime Services for the OS to use.
