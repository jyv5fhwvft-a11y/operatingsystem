The Complete Address Translation Flow

From C code to physical RAM. A step-by-step trace of how a single variable is generated, translated, and fetched by the hardware.

STAGE 1 The Real Program

Who generates the Logical Address?

When you write a program in C, the Compiler generates the machine code. It assumes your program owns the entire memory and starts at address 0. It assigns your variables specific logical addresses.

#include <stdio.h> int main() { int secret_number = 42; // Compiler assigns this to Logical Address 0x0040A000 int *ptr = &secret_number; printf("%d", *ptr); // CPU must fetch data from 0x0040A000 return 0; }

STAGE 2 The Hardware Journey

1. CPU Execution
The CPU executes the `printf` instruction and asks for data at the Logical Address.
Logical Address: 0x0040A000
2. MMU Splits the Address
The MMU divides the 32-bit logical address into a Page Number (VPN) and an Offset.
VIRTUAL PAGE NUMBER (VPN)0x0040A
OFFSET0x000
3. Page Table Lookup
The MMU looks up the VPN (0x0040A) in the OS Page Table to find the Physical Frame Number.
VPN 0x0040A → Physical Frame: 0x01A05
4. MMU Builds Physical Address
The MMU replaces the VPN with the Physical Frame Number. The Offset stays exactly the same.
PHYSICAL FRAME0x01A05
OFFSET0x000
Physical Address: 0x01A05000
5. RAM Access
The Memory Controller sends the physical address to the RAM chip.
RAM returns the value: 42

STAGE 3 Why do we do this?

1. Security (Isolation)

Because the CPU only generates logical addresses, your C program has absolutely no idea that the data actually lives at physical address 0x01A05000. It cannot read another program's memory because it doesn't know the physical address.

2. Flexibility (Virtual Memory)

The OS can move secret_number around in physical RAM (e.g., swap it to the hard drive and bring it back to a different physical frame). Because the Page Table is updated, the logical address 0x0040A000 remains exactly the same to the program.
