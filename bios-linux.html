Linux BIOS Boot

The legacy Linux boot process using MBR and GRUB. From the BIOS ROM to the systemd login prompt.

The Definition

The Linux BIOS boot process uses legacy 16-bit firmware to initialize hardware and load the Master Boot Record (MBR). It relies on a bootloader (typically GRUB Legacy or GRUB2) to navigate the file system, load the Linux kernel (vmlinuz) and the initial RAM disk (initrd), before transitioning to 32/64-bit protected mode and handing control to the kernel to start systemd or init.

🍎 The 5th Grader Analogy
Imagine a Multi-Stage Rocket Launch.

The BIOS is the launchpad. It fires the first tiny booster (MBR). That booster is too small to reach space, so it ignites the second stage (GRUB Stage 1.5) to break through the atmosphere. Then, the main stage (GRUB Stage 2) takes over, shows the astronauts a menu of destinations, and finally detaches to let the actual spaceship (the Linux Kernel) fly to the moon (systemd)!

⚙️ The Technical Analogy
Legacy BIOS is restricted to 512 bytes in the MBR. GRUB solves this by using a multi-stage chain-load. boot.img (in the MBR) loads core.img (in the post-MBR gap).

core.img contains filesystem drivers, allowing it to read /boot/grub/grub.cfg. From there, it loads the vmlinuz kernel and initrd.img into RAM, switches the CPU to Protected Mode, and jumps to the kernel entry point.
