1

Entry & Implicit Lock

When a thread calls a monitor method, it must first acquire the implicit lock. If the monitor is already occupied, the thread waits in the Entry Queue. Only one thread can ever be in the Monitor Body at a time.

2

The wait(cv) Operation

If the thread discovers it cannot proceed (e.g., buffer is full), it calls wait(cv). This atomically releases the lock and moves the thread to the Condition Queue. Crucially, this allows a thread from the Entry Queue to enter the Monitor Body.

3

The signal(cv) Operation

When a thread makes a resource available, it calls signal(cv). This wakes up one thread from the Condition Queue. In Mesa semantics, the woken thread moves to the Entry Queue to re-acquire the lock. In Hoare semantics, the signaler immediately hands the lock to the woken thread.

4

Exit & Release

When the thread finishes its work inside the monitor, it calls exit(). This releases the implicit lock, allowing the next waiting thread from the Entry Queue to enter. The cycle then repeats.
