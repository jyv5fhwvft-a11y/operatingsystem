The Linux UEFI River Flow

Watch how UEFI passes control through its phases, verifies Secure Boot, loads GRUB, and hands off to systemd.

SEC Phase
CPU starts at 0xFFFFFFFF · Firmware verified
PEI Phase
Memory Initialization
16GB DDR4 initialized · HOB List created
DXE Phase
Driver Execution Environment
45 UEFI Drivers loaded · ESP discovered
Boot Manager (BDS) & Secure Boot
Loads shim.efi from ESP (fs0:)
UEFI verifies shim.efi -> shim verifies grubx64.efi
GRUB2 Loader
grubx64.efi reads /boot/grub/grub.cfg
Displays menu · User selects Linux kernel
Kernel & Initrd Loading
Loads vmlinuz and initrd.img into RAM
Uses UEFI LoadImage() and StartImage()
ExitBootServices()
GRUB2 terminates UEFI Boot Services
Hands off system control to Linux Kernel
systemd Startup
Linux Kernel mounts root FS and starts PID 1
systemd targets reached · Login prompt

🐧 The UEFI Secure Boot Advantage

Because UEFI verifies every `.efi` file before execution using cryptographic signatures, Linux uses a "shim" to bridge the gap between Microsoft's keys (in the firmware) and the Linux distribution's keys.
