The Core Question of L10

Every program you compile assumes it owns all of memory and starts at address 0. But five programs are running simultaneously on one machine. How does each one get its own private view of memory — without any of them knowing about the other four?

🎯 The Illusion of Private Memory

Every program genuinely believes it starts at address 0

What the compiler emits

When you compile int x = 5;, the compiler emits something like movl $5, 0x400500(%rip). That address is a logical address — not the real physical RAM address. It's the address the program thinks it's using.

What actually needs to happen

The CPU must translate every logical address into a real physical RAM address before issuing the actual memory access. This translation is invisible to the program — that's the whole point.

Why this must be hardware, not software

Software translation would require executing code on every memory access — impossibly slow. The MMU (Memory Management Unit) does it in hardware, in parallel with the memory access itself. Zero overhead in the common case.

Two programs, same logical address, different physical
PROC A phys base 0x10000
PROC B phys base 0x50000
PROC C phys base 0x90000
0 0x40000 0x80000 0xC0000

All three processes believe their code starts at logical address 0. The hardware maps each one to a different physical region.

🏨 Analogy 1 · The Hotel Room Numbering Illusion

Every guest thinks they're in Room 100

The setup

Imagine a large hotel resort. Every single guest checking in receives an automated room booklet that says they're staying in "Room 100" — the same number for every guest. When they go to find their room, they use a master keycard lock.

The mechanism

The hotel's physical architecture silently maps each guest's "Room 100" to a completely different floor. Guest A's Room 100 → physical Room 500. Guest B's Room 100 → physical Room 800. Neither guest knows about the other.

The bound check

Guest A paid for a 10-room suite starting at Room 500 (Base = 500, Bound = 10). If Guest A tries to open "Room 115", their keycard fails — 15 > 10, out of their allotted range. That's a bounds exception.

💡
The whole point: the hotel is shared (one physical building), but each guest experiences a private view (their "Room 100"). The master keycard lock (hardware) enforces the mapping and the boundary.

🔢 Analogy 2 · Array Pointer Index

Base is the array start. Bound is the length check.

The structural match

Base-and-bound protection behaves identically to a safe compiler runtime wrapper around a raw byte array pointer. The Base register functions as the absolute starting array memory address (Array[0]), while the Bound register acts as a strict if (index >= length) array bounds check.

What C code looks like

int arr[10];
int i = 5;
if (i >= 10) error();
arr[i] = 42; // safe

The difference

In C, the bounds check is your responsibility — the compiler doesn't enforce it. In hardware, the bound check is mandatory on every access — the CPU enforces it. Same concept, impossible to bypass.

🧭 System Cohesion — Where L10 Sits

The first memory mechanism — and the one paging will replace

Relies On · L02 (Dual-Mode Barrier)

Relies on Ring 0 privileges to lock the physical Base and Bound registers so user threads cannot change their own memory space walls. Without the barrier, base/bound protection is worthless — the program could just rewrite its own limit.

Feeds Into · L11 (The Paging Model)

Serves as the historical precursor that proves contiguous variable-sized memory allocations lead to severe external fragmentation, driving the invention of fixed-size paging.

The trajectory of Module 3

L10 — base + bound (contiguous, one region per process)
L11 — paging (fixed-size pages, eliminates external fragmentation)
L12 — TLB (hardware cache for address translation)
L13 — virtual memory (demand paging, page replacement)

💡
Base and bound is obsolete in modern systems — but it's the simplest possible translation mechanism, and it establishes the vocabulary (logical, physical, bounds check) that every later mechanism reuses.

📖 Core Breakdown — The Translation Formula

One addition. One comparison. That's the whole mechanism.

The check that precedes it
if (logical < 0 ||

Why the check comes first

If you translate first and check later, an out-of-bounds access could overwrite another process's memory before you catch it. The check must gate the translation — the illegal write must never reach physical RAM.

Where this runs

In the MMU, in parallel with the memory access, before the physical address goes out on the bus. If the check fails, the MMU fires a trap and the access never happens — the physical memory is untouched.

📖 Core Breakdown — The Base Register

Where this process's memory actually starts

Base register in the MMU
BASE REG
Physical starting address · 32/64-bit
0x10000
PHYSICAL RANGE
0x10000 → 0x10000 + bound
all memory accesses from this process land here
What the base register holds

A physical CPU tracking chip that stores the absolute starting physical address of a program's active memory slot. When the OS loads your program at physical address 0x10000, that value goes into the base register.

How it gets set

When the OS schedules your process onto the CPU, it does a context switch — and part of that switch is loading your base register value from your PCB. That's why the register is per-process, even though the CPU has only one.

The magic

The program never knows what value is in its base register. It only ever sees logical addresses. The base is a translation offset applied transparently by hardware.

📖 Core Breakdown — The Bound Register

How big is this process's territory? Don't touch beyond.

What the bound register holds

The maximum allowable logical address (or equivalently, the size of the program's memory region). Every logical address is checked against it before translation.

The check

If logical >= bound, the MMU raises a trap. The kernel catches it, sees a SIGSEGV, and terminates the process. The physical memory beyond the bound was never touched.

Why this is the security primitive

Without the bound check, base-only translation would let a buggy pointer access any physical memory — including other processes' code. The bound is what turns translation into isolation.

💡
The complete package: base gives you relocation. bound gives you protection. Together they're the minimum viable memory isolation mechanism — the ancestor of every modern memory protection scheme.

📖 Core Breakdown — The Bounds Exception

The hardware trap that stops illegal writes

What happens on a bounds violation
✅
logical = 450 · bound = 2000
450 < 2000 → translate → physical = 450 + 14000 = 14450
🛑
logical = 2100 · bound = 2000
2100 ≥ 2000 → BOUNDS EXCEPTION → process killed
The sequence, in order

1. Program issues a load/store to logical address X
2. MMU compares X against the bound register
3. If X ≥ bound: fire trap, don't translate, don't touch memory
4. Kernel trap handler runs in Ring 0
5. Kernel sees offending process, sends SIGSEGV
6. Process terminates, siblings survive

The key guarantee

Step 3 is critical: the fault happens before any physical memory access. There is no moment where a rogue pointer could sneak a write into another process's memory. Isolation is absolute.

🔀 Multiple Processes — Same Logical, Different Physical

The whole point: each process gets its own base

Live · Three processes, same logical address 1000
PROC A base=0x10000 · bound=0x4000
PROC B base=0x50000 · bound=0x4000
PROC C base=0x90000 · bound=0x4000
0 0x40000 0x80000 0xC0000
logical addr 1000 in PROC A → phys 0x10000 + 1000 = 0x10400
logical addr 1000 in PROC B → phys 0x50000 + 1000 = 0x50400
logical addr 1000 in PROC C → phys 0x90000 + 1000 = 0x90400
Same address, three destinations

All three programs think they're writing to address 1000. Each one is actually writing to a completely different physical location. None of them can see the others' data.

The illusion maintained

From the program's perspective, memory looks identical in every process. It has no way to detect that its "address 1000" is not the same as another process's "address 1000".

Why this works

The MMU holds the current process's base in a register. When the OS context-switches, it saves one base register and loads another. The next instruction from the new process gets translated with a different base — instantly, transparently.

💻 Code — Base/Bound Check in C

The logic the MMU implements in hardware

base_bound.c
// This logic runs in the MMU hardware on every access.// Shown here in C for clarity.typedef struct {    uint64_t base;    uint64_t bound;} mmu_context_t;// The one operation that makes isolation workint translate(mmu_context_t* ctx,              uint64_t logical,              uint64_t* physical) {    // Bound check — must happen BEFORE translation    if (logical >= ctx->bound) {        return -1;  // BOUNDS EXCEPTION    }    // Translate    *physical = logical + ctx->base;    return 0;  // success}// On failure, the kernel does something like this:void handle_trap(task_t* t) {    printk("segfault at logical addr, pid %d\n", t->pid);    send_signal(t, SIGSEGV);    kill_process(t);}
The critical ordering

Note that the bound check is first. If it were after the translation, an illegal access could be translated to a valid-looking physical address and the write would happen before the fault. The order is the security property.

What "in hardware" really means

The MMU does this in parallel with the memory access — the check and the translation happen simultaneously, and only if both succeed does the read/write reach the RAM chip. Software version shown here is just for clarity.

Why the program can't bypass it

The program doesn't execute translate(). The hardware executes it on the program's behalf, before the program's instruction completes. The program has no code path that skips this.

⚠️ Problem 1 — External Fragmentation

Base/bound works only if you can find contiguous space

The fragmentation problem
PROC A100 MB
gap
PROC B120 MB
gap
PROC C150 MB
gap (200MB)
💡
Process D needs 250 MB contiguous. There is 200 MB free — but split across multiple gaps. Process D cannot run despite enough total memory existing.
The problem

Base/bound requires each process to occupy a single contiguous region of physical memory. When processes start and stop, memory becomes fragmented — small gaps between allocated regions.

Why it's severe

Over time, fragmentation can consume 30–50% of physical memory. The system runs out of usable space even though there's plenty of free memory scattered in gaps. This is external fragmentation.

The mitigation (partial)

Compaction — periodically shift all processes together to consolidate free space. But this is expensive (copy hundreds of MB) and requires stopping everything during the copy.

The real fix

Give up on contiguity entirely. Split memory into fixed-size pages and let any page be anywhere. That's paging — L11.

⚠️ Problem 2 — Rigid Allocation Limits

A process can't easily grow or share

The problem

A process's bound is set at load time. If the process needs more memory later (e.g., grows its heap), the OS must find a bigger contiguous region and move the entire process — expensive, and impossible if the adjacent region is occupied.

Sharing is impossible

Two processes running the same binary (e.g., 30 Chrome processes) each need their own full copy of the code. The base/bound model has no way to share physical memory between processes — every byte is private.

The waste

30 Chrome processes × 50 MB shared code = 1.5 GB wasted. On a modern system with paging, that same scenario uses 50 MB total — one shared copy, 30 page tables pointing to it.

💡
The pattern: base/bound was designed for a single-program world. As soon as you need dynamic sizing or sharing, the model breaks. Every subsequent mechanism (paging, segmentation, virtual memory) exists to fix these two limitations.
The two fatal limitations

Formal Definition

A physical CPU tracking chip that stores the absolute starting physical address of a program's active memory slot.

Plain Translation

( Where the process's memory starts in real RAM. Added to every logical address. )

Where it lives

The MMU holds a base register per CPU core. The OS updates it on every context switch.

The security role

Without a bound check, an out-of-range logical address could translate to another process's physical memory. The bound is what makes translation safe.

🌍 Real World — x86 Segmentation

Base/bound did ship in real hardware — as x86 segmentation

What x86 did

The original Intel 8086 introduced segmentation: a segment base + limit pair, essentially base-and-bound per segment. Programs referenced memory as segment:offset — the offset is the logical address, the segment base is where that region starts.

Why it's called base/bound

Each segment has a base (where it starts in physical memory) and a limit (its size). The 80286 introduced hardware protection using these — an access beyond the limit fires a general protection fault. This is textbook base-and-bound.

Why it didn't survive

Segmentation had the same fragmentation problem as pure base/bound. And managing 6 segments (code, data, stack × local/global) was complex. Linux famously ran with a single flat segment covering all of memory, effectively disabling segmentation in favor of paging.

💡
Modern x86_64 still has segment registers, but they're mostly vestigial — the only one that still does something is FS/GS, used for thread-local storage. Paging is what actually isolates memory now.

🔮 The Path to Paging

Base/bound works — until it doesn't

What base/bound got right

✓ Concept of logical vs physical addresses
✓ Translation on every access
✓ Hardware-enforced bounds check
✓ Per-process context via base register
✓ The vocabulary every later mechanism reuses

What it got wrong

✗ Requires contiguous physical memory
✗ Leads to severe external fragmentation
✗ No sharing between processes
✗ Process growth requires relocation
✗ Fixed-size region allocated at load

The insight that changes everything

Every one of those problems comes from requiring contiguity. If a process's memory didn't have to occupy a single physical region, all of these constraints would dissolve. Paging is the mechanism that removes contiguity — and it's the subject of L11.

🛑 Three Student Pitfalls

What beginners get wrong about relocation

PITFALL 01
"The base register holds the logical starting address"
No — the base register holds the physical starting address. The logical start is always 0 (that's why every process thinks it starts at 0). The base tells the MMU where to translate address 0 to in physical RAM.
PITFALL 02
"Bounds checks happen in the kernel"
No — the check is in hardware. The MMU checks on every access. The kernel is only invoked after the trap fires. If the check were software, a program could simply skip it.
PITFALL 03
"Physical address = logical × base"
It's addition, not multiplication. phys = logical + base. If you see any textbook using multiplication, it's wrong. (Segments in x86 are also additive, though some ARM segments use scaling — but that's not what we're covering here.)
🌍 Real World — Where You've Seen This in Action

Base/bound concepts still appear everywhere

Modern x86 segments

Still present in the architecture. FS and GS segments are used by Linux and Windows for thread-local storage — each thread's FS base points to its own TLS block. Same concept, narrow use.

Watchdog timers in hardware

Some embedded SoCs use base/bound-style hardware firewalls. A DMA controller can only write to addresses between base and bound — enforced in silicon, unmodifiable from software.

Sanitizer tools

AddressSanitizer, HWASan, and Memory Sanitizer use the same conceptual model — every pointer dereference is checked against a known-safe region. Same idea as base/bound, applied at compiler-runtime scale.

Modern MMU entries

Every page table entry has a base (frame number) and permissions (a form of bound). The base/bound model is the conceptual ancestor of every modern entry.

🏆 Grand Summary — L10 Key Takeaways

Four things to walk out with

01

Logical vs physical addresses: programs see logical addresses (starting at 0). The MMU translates each to a physical address. Programs never see physical addresses.

02

Base and bound is the simplest translation mechanism: physical = logical + base, with a bound check first to reject out-of-range accesses.

03

The bound check is the security primitive. Without it, translation alone would let buggy pointers corrupt other processes' memory. With it, isolation is absolute.

04

Base/bound has fatal limitations: external fragmentation, no sharing, no dynamic growth. Paging (L11) fixes all of these by removing the contiguity requirement.
